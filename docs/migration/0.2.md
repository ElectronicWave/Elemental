# Migrating from 0.1 to 0.2

0.2 is a breaking release at every layer. The tables below list the public
removals, renames, and signature changes that require application updates;
there are no compatibility re-exports for the old paths.

## Packages, features, and CLI

| 0.1 | 0.2 |
| --- | --- |
| `crates/demo` / `demo` binary | `crates/launchpad` / `launchpad` binary |
| Per-driver subcommands (`demo vanilla ...`) | Driver id is a positional argument (`launchpad vanilla ...`) |
| `--runtime-executable PATH` | `--runtime-path DIR` for runtime homes, or `RuntimeOptions::set_runtime_override` |
| `shared-json` without `shared` | Forwarded features now enable their parent modules; `yggdrasil-auth` enables `core` and `launcher` |
| No offline or Yggdrasil features | New `yggdrasil-auth`, `authlib-injector-embed`, and `offline-server` features |

## Core and runtime

| 0.1 | 0.2 |
| --- | --- |
| `elemental_core::consts` | Use `VersionJsonPlatform::current().natives_dir_name()` |
| `elemental_core::hash::{sha1, file_sha1, async_file_sha1}` | Removed; use the `sha1` crate directly |
| `Version<T>` implements `Ord` | `MinecraftVersion::parse(raw)?.key()` provides semantic ordering |
| `runtime::resolve_runtime(...)` | `RuntimeResolver::new(providers).resolve(major_version).await` |
| `provider::with_runtime_providers(...)` global override | `RuntimeResolver::new(...)` or `LauncherBuilder::runtime_providers(...)` |
| `Distribution::cached` / `find_cached_by_java_major` | `RuntimeResolver::distributions()` and `RuntimeResolver::resolve(...)` |
| Public `Distribution` fields, `build_from_root`, and `build_from_executable` | Private fields with `path()`, `release()`, `provider()`, and `executable()`; implement `RuntimeProvider` over runtime-home paths instead |
| `DistributionReleaseData::parse*` returning `Self` | Now return `Result<Self>` |
| `anyhow` errors in core | `runtime::Error`, `storage::Error`, and `launcher::Error` |
| `LaunchCommand { program, args }` | `runtime`, `jvm_arguments`, `main_class`, and `game_arguments`; use `program()` and `arguments()` |
| `spawn_command_logged`, `run_logged_process`, `ProcessLogLine`, and `LoggedChild` | Removed; spawn the command and consume the child streams yourself |
| `Storage::new_ensure_dir(...)` | `Storage::new(...)` followed by `ensure_root().await` |

## Authentication

| 0.1 | 0.2 |
| --- | --- |
| `auth::authorizer` | `auth::authorizers` |
| `UserCredential` | `Credential` with `CredentialKind`, `xuid`, `client_id`, and optional `auth_server` |
| `Authorizer::authorize() -> UserCredential` | `authorize() -> Self::Account`, then `Account::credential()` |
| `Authorizer` without associated account | `Authorizer::Account`, `id()`, and `name()` are part of the contract |
| `MicrosoftAuthorizer<F: Fn(String, String)>` | Handler returns `Result<(), Box<dyn Error + Send + Sync>>` |
| `anyhow` authentication errors | `auth::Error` and `auth::Result` |
| No account persistence or textures | `AccountStore`, `AccountRegistry`, `AccountIndex`, skin/cape APIs, and Yggdrasil accounts |

## Launcher and drivers

| 0.1 | 0.2 |
| --- | --- |
| `Launcher::catalog(catalog)` | `DriverCatalog::for_driver(driver)?` |
| `driver::inspect::InstalledInstance<L, VL>` | Removed; use `Launcher::inspect_instances()` and `Instance`, or detect a driver through `InstalledDriver` |
| `PrepareInstanceRequest` + `prepare_instance(...)` | `prepare(instance_name, DriverSpec, &RuntimeOptions)` |
| `Launcher::new` / `Launcher::with_layouts` | `Launcher::builder()` with `storage_root`, layouts, `runtime_providers`, and `origin_overrides` |
| `LaunchCommandResult` | `build_launch_command` returns `LaunchCommand`; the runtime is `command.runtime` |
| `build_launch_command(prepared, authorizer, options)` | `build_launch_command(prepared, &Credential, &RuntimeOptions, &LaunchOptions)` |
| `LaunchOptions = VersionJsonLaunchConfig` | `LaunchOptions` for branding and arguments; Java settings moved to `RuntimeOptions` |
| `VersionJsonLaunchConfig::set_runtime_executable_path(...)` | `RuntimeOptions` with `set_runtime_major_version(...)`, `set_runtime_validation(...)`, or `set_runtime_override(...)` |
| `launch_prepared_instance(prepared, authorizer, options)` | Adds `&RuntimeOptions`; also new `launch(command)` and `launch_instance(...)` |
| No prepared instance metadata | `PreparedInstance::info() -> PreparedInstanceInfo` |
| `driver::catalog::{Catalog, Release}` | `GameVersionCatalog`, `LoaderVersionCatalog`, `GameVersion`, and `LoaderRelease` |
| `FabricCatalog`, `ForgeCatalog`, `NeoForgeCatalog`, ... and their `*Release` types | `DriverCatalog` plus `GameVersion` and `LoaderRelease` |
| `FabricLaunchConfig`, `ForgeLaunchConfig`, ... | `RuntimeOptions` plus `LaunchOptions` |
| `FabricInstallStatus`, `ForgeInstallStatus`, ... | `VersionJsonInstallStatus` for profiled families; `InstallerInstallStatus` for installer families |
| `anyhow` errors in driver | `driver::Error` and `driver::Result` |
| Family-specific endpoint structs | `OriginEndpoints<O>` or family aliases such as `FabricEndpoints`; use `rewrite_known_or_keep` for optional rewrites |
| `Driver::inspect(&InstanceProbe<L, VL>)` | `Driver::inspect(&InstanceProbe)` |
| `#[async_trait]` on `Driver` | `#[async_trait(?Send)]`; custom drivers must implement `prepare` and `load_prepared` |
| Family-specific prepare/load results | `prepare(&PrepareRequest)` and `load_prepared(...)` return `PreparedVersionJsonInstance` |
| `version_json::{direct_profiled, launch}` module paths | Removed or reorganized; runtime options live under `driver::launch` |
| `VersionJsonLaunchConfig` | Split into `RuntimeOptions` and `LaunchOptions` |
| `VersionJsonLaunchBuilder` setters and async `build_command` | New constructor takes `Credential`, `LauncherVariables`, and extra arguments; `build_command` is synchronous |
| `version_json::{build_version_json_launch_command, build_version_json_launch_builder, launch_version_json_instance, launch_wrapped_version}` | Removed; use `Launcher::build_launch_command` and `Launcher::launch` |
| `version_json::prepared::{prepare_version_json, persist_version_json, load_prepared_version_json}` | Removed; use the `Driver` trait and storage extensions |
| Installer family result types | `LaunchedInstallerFamilyVersion` and `PreparedInstallerFamily*` removed; drivers return common prepared/launched types |
| Installer profile helpers | `ensure_installer_profile_libraries_downloaded` -> `submit_installer_profile_libraries`; `prepare_installer_launch_version` -> `persist_installer_launch_version`; several path/profile helpers were removed or made private |

## Downloads and shared infrastructure

| 0.1 | 0.2 |
| --- | --- |
| `downloader::core::{ElementalDownloader, DownloadSession, ...}` | Types are re-exported from `downloader` |
| `ElementalDownloader::create_named_session` / `create_unnamed_session` / `create_session` | `downloader.session(name).open().await?`; configure the builder first |
| `ElementalDownloader::run_plan` / `execute_plans` / `execute_planner` | Removed; open a session, `submit(...).await?`, then `finish().await?` |
| `DownloadSession::add_task(s)` / `add_plan` | `submit(DownloadBatch)` or `submit(task)` |
| `DownloadSession::finish() -> ()` | `finish().await? -> DownloadReport`; call `success()` to validate |
| `DownloadSession::{close, finish_snapshot, remove, wait_empty}` | `finish()` or `cancel()` consumes the session; use `wait_idle()` and dropping aborts it |
| `DownloadSessionSnapshot` | `SessionSnapshot`; progress uses `DownloadProgress` and the event streams |
| `TaskExecutionFailure` | `DownloadFailure`; reports expose failures through `DownloadReport::failures()` |
| `DownloadSessionRequest`, `DownloadExecutionPolicy`, `DownloadPlan`, `DownloadPlanner` | Session builder: `parallelism`, `retry`, `failure_policy`, `rate_limit`, and `headers` |
| Public `DownloadTask` fields and `new(url, path, expected_size, sha1)` | Private fields; `DownloadTask::new(url, path).size(...).sha1(...).header(...)` |
| `max_connections` / `set_max_connections` | `max_concurrent_downloads` / `set_max_concurrent_downloads` |
| `no_cached_materializer` / `hardlink_cached_materializer` | `without_cache` / `with_hardlink_cache` |
| `HardlinkCachedMaterializer` / `NoCachedMaterializer` | `HardlinkCacheMaterializer` / `UncachedMaterializer` |
| `Materializer::resolve(...)` | `Materializer::try_reuse(...)`; custom materializers also implement `staging_path(...)` |
| `anyhow` download and jar errors | `infra::Error` and `infra::Result` |
| `shared::version::Migrator` | `shared::migrator::Migrator<Stored, Current>` with `migrate` and `encode` |
| `VersionControlled::version` / `is_up_to_date` | `Versioned::version`; `VersionControlled::with_version` |
| `Persistor<V: VersionControlled>` | `Persistor<V>` without the version bound; `NoPersistor` now loads `None` |
| `Loader<M, V, P>` / `ProfileLoader<M, C, P>` | `Loader<M, S, V, P>` / `ProfileLoader<M, S, C, P>` |
| `Scope::Custom(path)` | `Scope::Directory(path)` |
| `Profile { name, config, version }` | The `name` field is removed |
| Private JSON/TOML file persistors | `JsonFilePersistor` and `TomlFilePersistor` are public; `MemoryPersistor` is new |

## Objects and schemas

| 0.1 | 0.2 |
| --- | --- |
| `anyhow` object-pool errors | `object::Error` and `object::Result` |
| `drop_value`, `drop_entry`, `fulfill` returning `()` | Return `bool` or `Result<bool>` |
| `ObjectPool::remove_value` / `remove_entry` returning `()` | Return `bool`; `shutdown_local()` does too |
| `provide_with_shutdown` generic closure bounds | `ShutdownCallback<T>` with a blanket implementation for async closures |
| `schema::forge::maven_metadata::*` | `schema::maven::*` |
| `LaunchMetaVersionData::release_time: String` | `jiff::Timestamp` |
| `PistonMetaLibraries::downloads` | `PistonMetaLibraries::source`, either downloads or Maven coordinates |
| Quilt `hashed` and `intermediary` non-optional | Now `Option<...>` |
