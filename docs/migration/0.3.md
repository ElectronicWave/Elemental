# Migrating from 0.2 to 0.3

0.3 makes launcher futures usable from runtimes that require `Send`, such as
`tokio::spawn`, `axum`, and TUI kernels.

## Launcher and drivers

| 0.2 | 0.3 |
| --- | --- |
| `Driver` used `#[async_trait(?Send)]` | `Driver` uses `#[async_trait]` and requires `Send + Sync` |
| Custom drivers could store non-`Send` state | Custom drivers and their sources must be `Send + Sync` |
| `Launcher` async methods returned `!Send` futures | `Launcher` async methods return `Send` futures |
| `Launcher::inspect_instances()` returned `Vec<Instance>` and failed on any corrupt instance | Returns `InspectReport { instances, failures }` so healthy instances remain usable |
| `MicrosoftAuthorizer<F>` required a generic handler type | `MicrosoftAuthorizer` stores a boxed handler; construct it with `MicrosoftAuthorizer::new(...)` |

Third-party `Driver` implementors only need to add `Send + Sync` bounds where
their state requires them; the trait methods themselves do not change.

## Catalog metadata

`GameVersion` and `LoaderRelease` no longer carry free-form description text.
Release channel metadata is named `channel` instead of `stream`.

| 0.2 | 0.3 |
| --- | --- |
| `GameVersion::description` | Removed; game versions only carry `id` and `channel` |
| `LoaderRelease::description` | Removed; use `channel` and other structured metadata |
| `LoaderRelease::with_description(...)` | Removed |
| `GameVersion::stream` | Renamed to `GameVersion::channel` |
| `LoaderRelease::stream` | Renamed to `LoaderRelease::channel` |
| `LoaderRelease::with_stream(...)` | Renamed to `LoaderRelease::with_channel(...)` |

Catalog descriptions were intended for human-facing text, but loader
implementations used them for diagnostic provenance notes. The fields are
removed so catalog metadata stays structured. Keep provenance notes in
documentation or application-level UI instead.
